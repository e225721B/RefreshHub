## 1. 全体の進め方 — なぜ「土台 → 3 分岐」なのか

~~~mermaid
flowchart LR
  Z["【土台】1 人で先に実施<br/>DB スキーマ / シード /<br/>ログインの仕組み /<br/>actions.ts のファイル分割"]
  Z --> A["A: 認証・ユーザー・通知"]
  Z --> B["B: 利用者・マッサージ師"]
  Z --> C["C: 管理者"]
  A --> M["統合・通し確認"]
  B --> M
  C --> M

  style Z fill:#fff4cc,color:#000000
  style M fill:#e6f2ff,color:#000000
~~~

**土台を並行させない理由**: DB スキーマ（`prisma/schema.prisma`）とシード（`prisma/seed.ts`）は
全員が依存する。3 人が同時に書くと解決できない衝突が起き、**全員の手が止まる**。
土台だけは 1 人が最後まで書き切り、`main` に入れてから分岐する。

### Git の使い方

| 手順 | 内容 |
|---|---|
| 1 | 土台は `feat/foundation` で作り、終わったら `main` にマージする |
| 2 | 分岐後は `feat/auth`（A）/ `feat/booking`（B）/ `feat/admin`（C）を切る |
| 3 | **1 日 1 回は `main` を自分のブランチに取り込む。**ためると解決不能な衝突になる |
| 4 | `.env` と `prisma/dev.db` は絶対にコミットしない（`.gitignore` 済み） |

### 触ってよいファイル（衝突を避けるための取り決め）

| ファイル | 触ってよい人 |
|---|---|
| `prisma/schema.prisma` / `prisma/seed.ts` | **土台担当のみ。**以降は 3 人で相談してから |
| `lib/slots.ts`（空き枠計算・テスト 14 件が通っている） | **原則さわらない。**変更が要るときは 3 人で相談 |
| `app/page.tsx`（予約画面） | **B のみ** |
| `app/admin/**` | **C のみ** |
| `app/login/**` `app/admin/users/**` `lib/notify.ts` | **A のみ** |
| `app/actions/*.ts` | ファイルごとに担当が決まっている（design.md の表を参照） |
