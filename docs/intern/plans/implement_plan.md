# Implement 実行計画

ゲート: `bash .claude/scripts/check-phase.sh implement` → **OK**（2026-09-08）

制約: **PoC を 1 時間で作る。** 実装期間はインターン残り 2 日。
プロジェクト: `massage-booking/`（Next.js 16.3.4 / React 19 / TypeScript / Tailwind / SQLite + Prisma）

## 全体像 — どの順で作り、何を確認してもらうか

データの土台 → 計算ロジック → 画面、の順に作る。
理由: 画面から作ると、表示されているものが正しいのか判断できない。
**空き枠の計算は目視で正しさを判断しにくい**ため、画面より先に作り、自動テストで確かめる。

| 順 | タスク | 学生に確認してもらうこと |
|---|---|---|
| T-0 | セキュリティ確認（.gitignore） | DB ファイルと秘密情報がコミット対象に入っていないこと |
| T-1 | Prisma スキーマと DB 作成 | 4 テーブルが設計どおりに作られたこと |
| T-2 | シードデータ投入 | マッサージ師 4 名・ベッド 3 台・シフトが入ったこと |
| T-3 | 空き枠の計算ロジック + 自動テスト | テストが通ること（施術時間ごとの枠数、予約済みの除外） |
| T-4 | 予約画面（一覧表示） | 画面に空き枠が並ぶこと（AC-1 / AC-3 / AC-4） |
| T-5 | 予約の確定 | 予約すると一覧からその枠が消えること（AC-2） |
| T-6 | 管理者の予約状況画面 | 予約した枠がグリッドで埋まって見えること（AC-8） |
| T-7 | 利用ガイド（余力があれば） | ルールが 1 か所で読めること（AC-5） |

## セキュリティ確認（最初のタスクより前）

- [x] `.gitignore` に `node_modules/`、`.next/`、`.env*` が含まれている（create-next-app が生成済み）
- [ ] SQLite の DB ファイル（`*.db`）を `.gitignore` に追加する
- [ ] `.env` に接続文字列を置き、`.env.example` にサンプル値を置く
- [ ] シードデータは**仮名**のみ（実在の人名・メールアドレス・社員番号を入れない）
- [ ] 予約フォームの入力値を検証する（日付・時刻・施術時間が想定内か）
- [ ] 認証は MVP 外と設計で決定済み。**そのリスクを tasks.md に明記する**

## 進め方のリズム

各タスクで「予告 → 作業 → 確認」を守る。
確認結果（コマンドと出力、または画面の状態）は `docs/intern/tasks.md` に残す。
「動いた」とだけ書かない。確認できていないものは「未確認」と書く。
