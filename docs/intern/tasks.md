| I9-1 | 性別のチェックと施術者のチェックの関係 | **性別のチェックは、そのグループの施術者をまとめて ON / OFF する操作**にする（親子連動）。サーバーに渡す絞り込み条件は**「チェックの入っている施術者 id」の 1 種類だけ**。一部だけ選ぶと性別側は中間状態（■）になる |
| I9-2 | モーダルでの施術者・性別の変更 | **やらない。**変更できるようにすると、その場で担当とベッドを再探索する仕様がセットで必要になり、絞り込みとの二重管理になる（design.md D-5） |
| I9-3 | ブランチの土台 | `feat/booking-user-actions` から切る（stacked）。#9 で触る `WeekSchedule.tsx` の絞り込み欄が、まだ `main` に入っていないため |

**二重管理を避けたのがこのタスクの本質。**性別と施術者を別々の条件（AND）にすると、
「男性のチェックを外したら、個別にチェックしていた男性施術者も対象外になる」といった説明の要る挙動が生まれる。
条件を 1 種類に寄せたので、そもそもその状態が作れない。

### 担当候補の条件を 1 か所にまとめた理由

絞り込みの選択肢（チェックボックス）と空き枠計算が別々の条件で施術者を選んでいると、
**「チェックできるのに、その人の枠が絶対に出てこない」**状態が起きる。
`SELECTABLE_THERAPIST_WHERE`（`Therapist.active` と `User.active` の両方が true）を両方から使うようにした。

# 追加（2026-09-10）: 今日の過ぎた時間を選べないようにする

学生の指摘: 「今 15:00 過ぎているけど、**今日の 9:00 とかを選択できる**のを修正したい。その時間が過ぎたら選択不可にしたい」。

## 見つかった穴（画面だけの問題ではなかった）

判定に使っていた `isPast(date)` は**日付単位**で、「今日」を過去にできない。そのため今日の午前がずっと空きのままだった。
さらに **`createReservation` に過去時刻のチェックが無く、画面を灰色にするだけでは保存を止められない**状態だった
（Server Action はリクエストを直接投げれば呼べる）。**画面と保存の両方**を直した。

| 層 | 変更 |
|---|---|
| `lib/dates.ts` | `isStartPassed(date, hhmm, now?)` を追加。**ちょうど今始まる枠も選ばせない**（選んでいる間に過ぎてしまうため） |
| `lib/slots.ts` | `getAvailableSlots` に `notBefore?: "HH:MM"` を追加。この時刻より後に始まる枠だけを返す。**「今日かどうか」の判断はこの関数に持たせず**、呼び出し側が決める（日付を持たない関数のため） |
| `app/actions/booking.ts` | `fetchWeekAvailability` が**今日の分だけ** `notBefore` に現在時刻を渡す。`createReservation` は過去時刻を弾く（「過ぎた時間は予約できません」） |
| `app/WeekSchedule.tsx` | 「今」を状態として持ち、**1 分ごとに進める**（画面を開いたままでも古くならない）。過ぎたマスは灰色 + ツールチップ「過ぎた時間です」 |

**サーバーと画面で同じ判定を 2 か所に置いた理由**: サーバーだけだと、開いたままの画面は次の再取得まで古い枠を選べてしまう。
画面だけだとリクエストを直接投げられて保存できてしまう。**画面は体験のため、サーバーは正しさのため**に必要。
